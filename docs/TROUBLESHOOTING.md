# TraceCrypt Diagnostic Runbook & Troubleshooting Guide

**Document Version:** 1.0.0  
**Target Audience:** Air-Gapped Systems Administrators, Cryptographic Officers, Forensic Investigators  

---

## 1. Quick Diagnostic: System Health Check

Before troubleshooting individual subsystems, run the automated diagnostic health check:

```powershell
tracecrypt doctor
```

The doctor command evaluates:
1. Python runtime environment (3.11+ 64-bit AMD64)
2. Core and optional dependencies
3. Cryptographic algorithms (ML-KEM-768, ML-DSA-65, AES-256-GCM, SHA3-256)
4. Directory structure and file permissions
5. Ledger database integrity and WAL mode
6. Storage space and memory limits

If issues are found, follow the specific sections below.

## 2. Cryptographic Failure Modes & Remediation

### E-CRYPTO-01: `KeyPurposeMismatchError` / `InvalidKeyPurpose`
- **Symptom:** `package_document` or `decrypt_and_attribute` fails with "Certificate key purpose is not valid for operation".
- **Root Cause:** TraceCrypt enforces strict key separation. Attempting to use a signing key for KEM decapsulation, or a KEM key for signing, is rejected.
- **Remediation:**
  - Verify certificate purpose:
    ```powershell
    tracecrypt pki inspect-cert --cert "certs/recipient_signing.cert"
    ```
  - Ensure `recipient_spec` references the KEM certificate (`KeyPurpose.KEY_ENCAPSULATION`), and event signing uses the signing certificate (`KeyPurpose.DIGITAL_SIGNATURE`).

### E-CRYPTO-02: `ML-KEM Decapsulation Failure`
- **Symptom:** Recipient cannot unwrap document key; throws cryptographic decapsulation error.
- **Root Cause:** The encrypted ciphertext was targeted at a different recipient public key, or the private key does not match the public key in the certificate.
- **Remediation:**
  - Verify that the recipient's User ID matches the recipient slot in the `.tcdist` metadata.
  - Test raw keypair consistency:
    ```powershell
    python -c "from tracecrypt.crypto.pqc import MLKEMEngine; k=MLKEMEngine(); ct, ss1 = k.encapsulate(pub); ss2 = k.decapsulate(ct, priv); assert ss1 == ss2"
    ```

### E-CRYPTO-03: `CertificateExpiredError` or `CertificateRevokedError`
- **Symptom:** Operations rejected with certificate validation errors.
- **Remediation:**
  - Check certificate validity dates:
    ```powershell
    tracecrypt pki verify-cert --cert "certs/user.cert" --root-ca "certs/ca_root.cert"
    ```
  - If expired, re-issue a certificate from the offline Root CA.

## 3. Ledger & Consensus Troubleshooting

### E-LEDGER-01: BFT Consensus Quorum Failure ($n < 3f + 1$)
- **Symptom:** Nodes log `Timeout waiting for 2f+1 PRE-PREPARE / PREPARE / COMMIT votes`.
- **Root Cause:** In a 4-node cluster ($n=4, f=1$), at least 3 nodes must be online and communicating to reach quorum. If 2 nodes are down, consensus halts.
- **Remediation:**
  - Check the status of all 4 node processes:
    ```powershell
    Get-Process -Name "python"
    ```
  - Verify port reachability across node loopbacks (9101, 9102, 9103, 9104).
  - Restart failed node processes with their respective configuration files.

### E-LEDGER-02: Block Hash Mismatch / Merkle Verification Error
- **Symptom:** Node rejects peer block with `BlockHeaderHashMismatch`.
- **Root Cause:** Storage corruption or non-deterministic transaction execution.
- **Remediation:**
  - Stop the affected node.
  - Re-sync state from a healthy peer:
    ```powershell
    # Backup corrupt local ledger
    Move-Item "data/nodes/node4/ledger.db" "data/nodes/node4/ledger_corrupt.db"
    # Copy verified state from Node 1
    Copy-Item "data/nodes/node1/ledger.db" "data/nodes/node4/ledger.db"
    ```

## 4. Forensic & Watermark Recovery Issues

### E-FORENSIC-01: `WatermarkCorruptedError` (ECC Decode Failure)
- **Symptom:** `extract_watermark` throws `WatermarkCorruptedError: Reed-Solomon decoding failed`.
- **Root Cause:** The leaked image suffered severe physical degradation, extreme downsampling, or adversarial warping exceeding the Reed-Solomon error correction threshold.
- **Remediation:**
  - High-resolution re-scanning: Scan physical leak at minimum 600 DPI, uncompressed TIFF, 24-bit RGB.
  - Manual deskewing: Ensure page edges are orthogonal.
  - Contrast enhancement: Apply adaptive histogram equalization to boost sub-band DCT differentials.

### E-FORENSIC-02: `UnregisteredWatermark` (Verdict V7)
- **Symptom:** Blind extraction yields a valid 32-byte watermark ID, but forensic attribution outputs Verdict `V7`.
- **Root Cause:** The watermark was generated by a development or test run whose `DecryptionEvent` was never committed to the production ledger.
- **Remediation:**
  - Confirm the investigator is pointed at the correct production ledger replica, not a local scratch test database.

## 5. Storage & Database Remediation

### E-STORAGE-01: SQLite Database Locked (`sqlite3.OperationalError: database is locked`)
- **Root Cause:** A long-running read transaction or orphaned process holds an exclusive lock.
- **Remediation:**
  - Verify WAL mode is enabled:
    ```powershell
    sqlite3 "data/ledger.db" "PRAGMA journal_mode;"
    # Should output: wal
    ```
  - Ensure busy timeout is set to 30000ms.
  - Kill orphaned python instances locking the file.

### E-STORAGE-02: Corrupted Backup Verification Failure
- **Symptom:** `tracecrypt-restore` fails with `DigestMismatchError`.
- **Root Cause:** Storage media corruption or incomplete backup transfer.
- **Remediation:**
  - Inspect backup manifest:
    ```powershell
    python -c "import zipfile, json; z = zipfile.ZipFile('backup.tcbackup'); print(z.read('manifest.json').decode())"
    ```
  - Re-create backup from source node if accessible, or revert to the previous verified backup snapshot.
